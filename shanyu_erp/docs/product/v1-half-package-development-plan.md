# V1 半包报价可执行开发计划

> 状态：已确认并执行。业务基线为《山屿 ERP 系统需求一期 - 半包报价单 PRD》V2.0；老板最新确认高于文档。页面与导航统一使用“主材库”，V1 只实现其中的半包标准工程项，不实现主材 SKU。

## 1. 固定边界

- V1 交付账号权限、项目与统一空间、主材库中的半包标准工程项、半包报价、预计成本/毛利、审批、版本、导出和审计。
- 不实现施工计划、现场执行、收付款、实际成本、实际利润或对应页面。
- 不实现主材 SKU、铂屿木作定制明细或任何未提供的主材/木作模板字段；只保留已确认的角色与后续稳定关联能力。
- 空间名称为 1–6 个字符。金额数据库与计算过程保留 4 位小数，页面与导出显示 2 位。
- 老板可查看成本、毛利并管理标准价；主案不可取得这些敏感字段；木作仅建立固定角色，项目指派与木作模块进入 V2。
- 原始 Excel 公式不得直接作为可执行代码。已识别的 20 条复杂数量公式必须先形成逐项业务映射并经确认，未确认前不得臆造局部参数字段。

## 2. 分阶段执行

### 阶段 1：账号、会话与固定角色

- **数据库迁移**：建立用户、凭据、会话、审计事件及固定角色枚举；迁移必须完成 `up → down → up` 验证。
- **业务测试**：账号/手机号登录、错误凭据、12 小时/30 天会话、过期会话、退出撤销、密码和令牌不可明文返回或存储。
- **权限测试**：只有老板可查看/创建用户；主案、木作及预留角色均被服务端拒绝；请求头或请求体中的伪造角色不得改变当前身份。
- **浏览器验收**：老板、主案、木作三个演示账号分别登录；工作台显示正确角色；老板可进入“用户与权限”；主案/木作直接访问该页面被拦截；退出后返回登录页。
- **完成标准**：迁移可回滚，审计包含登录/退出/建号，API 和页面无凭据泄露，根目录 `lint/typecheck/test/build` 全绿。

### 阶段 2：项目与统一空间

- **数据库迁移**：建立稳定项目 ID、项目参与人、空间及空间排序；空间名称约束为 1–6 个字符，面积与已确认基础参数使用明确小数精度。
- **业务测试**：老板/主案创建项目；录入客户、地址、建筑面积和主案；添加、改名、排序、删除未被报价引用的空间；边界值和重复提交可预测。
- **权限测试**：老板可见全部项目；主案仅访问本人负责项目；木作和预留角色不能进入项目报价；服务端按角色与项目关系过滤。
- **浏览器验收**：项目列表、新建项目、项目概览和空间管理按设计稿走通；1 字与 6 字空间名成功，0 字与 7 字被明确拒绝。
- **完成标准**：项目/空间 ID 稳定，越权接口不泄露项目是否存在，不出现施工或财务入口，所有门禁全绿。

### 阶段 3：主材库中的半包标准工程项与 Excel 导入

- **数据库迁移**：建立导入批次、半包模板版本、8 个报价分区、标准工程项、销售价/成本价版本和原始来源行；发布后历史版本只读。
- **业务测试**：同一文件可重复校验且不会重复发布；8 分区、157 项、销售价 157/157、成本价 157/157 为发布阻断条件；第 56、101、163 行施工说明允许为空并产生已知提示。
- **权限测试**：老板可导入、校验和发布；主案只能读取已发布销售信息；木作和预留角色不能导入；主案接口、页面和日志展示不返回成本。
- **浏览器验收**：导航与页面标题使用“主材库”；完成选择文件、校验报告、差异定位、发布确认和已发布版本查看；不显示主材 SKU 表单。
- **完成标准**：机械对算差异为 0，失败批次不可发布，成功批次能被新报价稳定引用，完整步骤见第 3 节。

### 阶段 4：半包报价编辑与数量计算

- **数据库迁移**：建立报价、报价空间、行项目、选型、数量输入/计算结果、规则版本和 4 位小数金额；保存所引用模板与价格版本。
- **业务测试**：默认展示对应空间全部工程项；无公式数量可留空；已确认规则按项目/空间参数计算；金额为数量×销售价；空数量不误报异常；20 条复杂公式映射未确认的项目保持手工数量或阻断自动化，不新增字段。
- **权限测试**：老板和项目主案可编辑；木作及非参与人不可进入；主案不能修改标准价或通过请求体覆盖成本/销售基准。
- **浏览器验收**：空间切换、数量填写、材料选择、保存恢复、错误提示和小计刷新走通；金额显示 2 位，刷新后与服务端 4 位结果一致。
- **完成标准**：核心计价只有一个服务端实现，页面和导出不重复公式，源 Excel 样例逐行数量与金额对算差异为 0。

### 阶段 5：预计成本与毛利

- **数据库迁移**：建立报价版本的预计成本快照、毛利汇总及所引用成本版本；不建立实际成本或财务流水表。
- **业务测试**：行成本、分区成本、半包预计成本与毛利按同一快照计算；金额过程 4 位、展示 2 位；新成本版本不回写历史报价。
- **权限测试**：仅老板接口返回成本/毛利；主案在页面、接口、导出和日志展示均不能获得或推导敏感数据；木作与预留角色拒绝。
- **浏览器验收**：老板可查看成本毛利页及版本来源；主案用同一报价访问时页面无入口、接口 403/脱敏；不出现实际利润或收付款文案。
- **完成标准**：敏感字段负向测试覆盖所有传输面，源 Excel 样例预计成本/毛利对算差异为 0。

### 阶段 6：提交审批、版本、导出与审计

- **数据库迁移**：建立报价状态流转、提交快照、审批决定/原因、版本关系、导出记录和不可变审计详情。
- **业务测试**：草稿提交、待定价/待补充、批准、退回、特批、复制新版本及已批准只读；客户导出引用批准快照，金额显示 2 位。
- **权限测试**：主案只能提交本人项目；仅老板批准/退回/特批；无成本权限者的版本对比、导出和日志展示均脱敏。
- **浏览器验收**：主案提交、老板审批、退回后修订、批准后锁定、版本对比和客户导出全流程走通；浏览器下载内容抽查无成本字段。
- **完成标准**：状态不可绕过，批准快照不可原地修改，关键操作均可按人、时间、对象和原因追溯。

### 阶段 7：整体验收、真实项目对算与上线门禁

- **数据库迁移**：在全新数据库执行所有迁移、种子和回滚演练；记录迁移版本、耗时、备份和恢复结果，不临时修改生产数据。
- **业务测试**：完整回归 157 项导入、项目/空间、报价、成本毛利、审批、版本和导出；使用至少一个真实项目与现有人工报价对算。
- **权限测试**：按老板、主案、木作、项目经理、财务五角色执行接口矩阵和浏览器矩阵；检查附件/导出地址（若本期产生）也必须鉴权。
- **浏览器验收**：桌面主流程和关键窄屏页面通过；登录失效、空状态、错误状态、刷新恢复和下载均验证；不出现施工、财务、主材 SKU 或木作模板页面。
- **完成标准**：源 Excel 与真实项目两套对算均为 0 差异，备份恢复演练通过，所有质量门禁通过后才可标记 V1 可部署。

## 3. Excel 157 项导入与对算规程

### 3.1 唯一来源与字段映射

- 唯一源文件：`../半包报价单_v2.xlsx`，工作表“半包报价模板”，导入时记录文件 SHA-256、工作表名、导入人和时间。
- 只把工程项行导入标准工程项；分区标题、小计和工程汇总不能混入 157 项。
- 源字段固定映射：工程项目 `C`、单位 `E`、原始数量/公式 `F`、销售价 `G`、施工说明 `I`、成本价 `J`；同时保存源行号与分区顺序用于审计和机械对算。
- 分区及项数固定为：砌墙 19、客餐厅 45、卧室 40、阳台 3、厨卫 27、油漆 3、水电 17、其他 3，合计 157。
- 第 56、101、163 行施工说明保持空值，不补写内容；发布报告列为已知提示而非缺失阻断。

### 3.2 两段式导入

1. **校验批次**：解析到 staging，不创建可引用模板；校验 8/157 数量、必填字段、销售价和成本价、分区顺序、重复项、空说明例外及公式清单。
2. **发布批次**：只有零阻断差异且由老板确认的批次可一次性发布；生成不可变模板/价格版本和稳定工程项 ID。重复发布同一文件哈希必须被拒绝或明确复用，不能静默复制。

V1 导入会保留 F 列原始值/公式作为来源证据，但不会执行 Excel 字符串。源表当前包含 41 个工程项数量公式单元格；其中已识别的 20 条复杂/局部尺寸公式必须建立“源行 → 业务含义 → 所需已确认参数 → 服务端规则 → 样例期望值”映射并经确认。未确认项不自动计算，也不新增推测字段。

### 3.3 机械对算

发布前由独立比较器从源 Excel 与 staging/数据库各生成一份按源行号排序的规范化清单，逐项比较：

- 分区代码与顺序、源行号、工程项名称、单位；文本做首尾空格规范化后比较，不做同义词替换；
- 销售价、成本价以十进制定点数比较到 4 位，157 项两列都必须 157/157；
- 原始数量常量/公式文本、施工说明及三条允许为空的来源行；
- 8 个分区项数与总项数；任何一项差异都会阻断发布，并输出可定位到 Excel 行号的差异报告。

阶段 4 再以源 Excel 样例参数逐行比较数量、行金额、分区小计、直接费、管理费和总造价：内部值比较到 4 位，页面/导出比较到 2 位。阶段 5 同样比较预计成本和毛利。源样例通过后，阶段 7 必须再选择至少一个真实项目，以人工现行报价与系统批准快照逐行对算；两套对算都要求差异 0 才能上线。
