# 开发前最小决策与输入

> 目标：用尽可能少的人工决策尽快产生可本地部署版本。未对推荐项提出反对时，Codex 可按推荐默认继续。

## 已由老板评审确认

| 主题       | 已确认结论                                                                |
| -------- | -------------------------------------------------------------------- |
| 首个可运行里程碑 | V1 只做账号权限、项目/空间、半包基础库与报价、预计成本/毛利、审批、版本、导出和日志；主材、木作、第三方及全案细化进入 V2     |
| 审批规则     | 所有正式报价均需老板批准；定制项目逐项老板审批                                              |
| 折扣与抹零    | 除第三方代购外，各模块支持折扣（快捷 95%/98%）；所有模块支持抹零                                 |
| 第三方利润    | 第三方进入客户总额但排除对客总利润，不生成包含第三方的全部利润加总                                    |
| 初始半包数据   | 使用《半包报价单_v2.xlsx》的 8 分区、157 项；销售价和成本均完整。第 56、101、163 行施工说明保持空并提示后续补充 |

## 开始生成代码前仍需技术决策

| 主题        | 推荐默认                                                                             | 为什么需要你确认               |
| --------- | -------------------------------------------------------------------------------- | ---------------------- |
| 架构        | 接受 `architecture-proposal.md` 的 TypeScript 模块化单体方案                               | 这是之后更换成本较高的工程决策        |
| 本地数据库运行方式 | 安装 Docker Desktop 或等价 Docker 运行时，由 Compose 启动 PostgreSQL；当前电脑尚无容器运行时或 PostgreSQL | 没有数据库运行时就无法完成可持久化的本地部署 |
| Git 自动化边界 | Codex 可在功能分支提交；未经明确授权不推送远程 `main`                                                | 涉及远程仓库的外部状态变更          |

## 可由 Codex 直接决定

- 具体目录结构、代码规范、测试工具、ORM 和开发依赖；
- 可替换的本地文件存储、站内通知和本地账号适配器；
- 演示用户、演示项目和可重复初始化的 seed 数据；
- 不改变业务行为的界面微调和响应式适配。

## 本地可运行版本可以延后的输入

- 真实员工账号、正式密码和生产级权限分配；
- 公司 Logo、正式封面、签字样式和所有导出版式；
- 毛利预警阈值和例外特批阈值；
- 主材报价明细表正式文件；
- 铂屿木作定制正式模板和型号—价格数据；
- “毛利计算中，第三方代购……”截断规则的完整表述；
- 半包第 56、101、163 行施工说明（如需补充）；
- 主材库中待确认商品的真实商品销售价和成本价；
- 企业微信主体、应用、群机器人或消息推送凭据。

## 正式共享/上线前必须补充

- 部署主机、域名、HTTPS 和访问范围；
- 生产数据备份、恢复、密钥管理和附件存储策略；
- 首批真实用户与项目可见范围；
- 至少一个真实项目作为 Excel 对算和业务验收样本。
