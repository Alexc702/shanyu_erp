## 本次重点场景

| 场景 | 实测结果 |
|---|---|
| 新旧商品相同，仅记录版本/来源变化 | 规则允许更新 |
| 型号、规格、品牌、品名、单位变化 | 阻止自动更新 |
| 销售价或成本变化 | 阻止自动更新，即使用户总额看起来可能不变 |
| 颜色、属性、说明、图片变化 | 阻止自动更新 |
| 商品删除、报价快照不一致、玻璃门选色不完整 | 阻止，不清空原选型 |
| 只读预览 | 报价、明细、空间、半包行、审计、导出数据均未改变 |
| 无差异草稿自动应用 | 仅变更库/商品版本引用、revision、更新时间及审计；完整行字段比对通过 |
| 一份报价有差异，另一份无差异 | 差异报价原样保留；无差异报价独立更新 |
| QUOTED / RETURNED / APPROVED | 全部跳过，数据状态一致 |
| 从 QUOTED / RETURNED 继续编辑 | 继承原库、原价格、数量、手动标记、旧选色、折扣、抹零、原因和金额 |
| 历史派生草稿后续自动升级 | PROTECTED，数据不变 |
| 打开继承草稿/主材页面初始化路径 | 不隐式修复或重算，不追加主材需求 |
| 重复半包 version_item_id / sort_order | 精确对应原行→新行，未丢行或串行关联 |
| 发布库自动触发 | 新库发布事务内自动更新安全草稿，分析审计存在 |
| 重复执行 | 无二次 revision、无重复审计 |
| 预览后业务内容变化 | apply 重新分析并阻止 |
| 指定目标不再是已发布版本 | 停止，未修改 |
| 审计写入异常 | 引用变更一并回滚 |
| 并发库写入 | 更新事务持锁期间另一连接锁超时，防止夹入发布 |

## 说明与限制

- 安全性验证是合成数据和真实 PostgreSQL 约束/事务测试，不是对云端真实业务数据的升级验收。
- 原历史报价业务内容保留，不表示所有技术元数据逐字节不变：继续编辑时旧版本 is_current=false，新版本有新 ID、版本号和 DRAFT 状态。
- 在新代码部署前，云端仍使用原有逻辑。不能只复制 CLI 文件到旧镜像执行；需包含新的编译模块和继续编辑修复。
- 未修改旧的显式手动“更新主材库”操作语义；该入口仍需用户主动确认，不是安全自动脚本入口。
- 测试中最初缺少合成半包模板、状态字段和毛利字段导致的夹具失败均已修正；重复排序的断言改为按业务身份比较，精确引用映射断言保留。没有通过跳过失败用例获得以上结果。

脚本和使用步骤见 [主材库零影响自动更新](./main-material-safe-update.md)。
