# 山屿 ERP Context Map

系统以同一个稳定的装修项目身份串联报价、施工交付和财务结算，各上下文拥有自己的业务语言和变更节奏。

## Contexts

- [项目](./docs/contexts/project/CONTEXT.md)：拥有客户装修事项的稳定身份、场所、空间和参与人。
- [报价](./docs/contexts/quotation/CONTEXT.md)：产生、校验、审批和锁定各类报价版本。
- [基础库](./docs/contexts/catalog/CONTEXT.md)：管理标准工程价目、主材商品、模板和联动规则的受控版本。
- [施工交付](./docs/contexts/delivery/CONTEXT.md)：从已批准报价建立施工基准，管理计划、节点、进展和工程变动。
- [财务](./docs/contexts/finance/CONTEXT.md)：管理合同后的应收、收款、应付、付款、实际成本和实际毛利。
- [组织与授权](./docs/contexts/access/CONTEXT.md)：管理用户角色、项目指派和敏感数据可见性。

## Relationships

- **项目 → 其他上下文**：所有阶段共享稳定项目 ID，不因“报价转施工”创建第二个业务项目。
- **基础库 → 报价**：报价选择已发布的工程价目、商品和规则，并保存版本快照；基础库后续调价不回写历史报价。
- **报价 → 施工交付**：已批准报价版本成为施工基准；施工中的增减替换使用工程变动，不覆盖原报价。
- **报价 → 财务**：已批准版本和后续已批准变动提供合同/当前预计金额，预计成本不冒充实际成本。
- **施工交付 → 财务**：已批准变动及实际执行记录为财务对账和结算提供业务依据。
- **组织与授权 → 所有上下文**：同时使用角色和项目指派判定访问范围；成本、毛利和底价属于独立的敏感数据权限。
